# حالة مشروع تيوزدية عند التسليم

| الجزء | حالة الكود المصدر | ما يحتاجه للتشغيل الحقيقي |
|---|---|---|
| واجهة عربية Mobile-first بهوية تيوزدية | مُنجز | مراجعة صاحب المشروع على الأجهزة الفعلية |
| صفحات الورش وصورها والموقع | مُنجز | بيانات وصور الورش الفعلية، وSupabase |
| PWA تثبيت على الشاشة الرئيسية | مُعدّ في البناء | نشر عبر HTTPS واختبار آيفون/أندرويد |
| تسجيل الدخول OTP بالبريد | مُبرمج | Supabase Email Auth ومزوّد إرسال مناسب |
| حساب المشارك وحجوزاته | مُبرمج | تطبيق SQL وبيانات فعلية |
| مراجعة الطلبات وتأكيد الدفع يدويًا | مُبرمج | صلاحيات الإدارة والمطابقة في مزوّد الدفع |
| إصدار QR موقّع | مُبرمج | Netlify Functions وTICKET_SIGNING_SECRET |
| رفض مسح التذكرة ثانية | مُبرمج بقيد قاعدة بيانات ومعاملة | اختبار تكاملي حقيقي ومتزامن |
| لوحة مدير وموظفي استقبال | مُبرمج | حسابات موظفين حقيقية وتفويضات |
| تصدير Excel | مُبرمج | تشغيل التطبيق واختبار ملف التنزيل في المتصفح |
| بوابة دفع آلية + Webhooks | **غير مفعّلة** | عقد مزود الدفع وبيانات API واختبارات sandbox |
| إشعارات SMS آلية | **غير مفعّلة** | مزود SMS، اعتماد القوالب وموافقة الرسائل |
| نشر على Netlify | ملفات إعداد جاهزة | ربط المستودع والمفاتيح والتشغيل |
| اختبار npm build من بيئة التسليم | **غير ممكن هنا** لعدم اتصال npm | تشغيل `npm install && npm run build` في Netlify أو جهاز متصل |

## ملاحظات تشغيلية إلزامية

- لا تُنقل المفاتيح السرية داخل كود React مطلقًا.
- لا يُقبل أي QR كدخول دون تأكيد الخادم.
- لا تُقبل صورة إيصال كدفع متحقق دون مطابقته بمزود الدفع.
- لا تبدأ عمليات مالية حقيقية قبل تثبيت سياسة استرداد وشروط قانونية والتأكد من جميع الاختبارات.
